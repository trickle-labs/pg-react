# v0.50.0 operator signals

Use this query pack for one administrative domain after v0.50 qualification.
The current manifest does not name or admit a workload. Run intent and receipt
queries as that entity's execution role. The `operational_activity_v1` view
returns only that role's intent, React work-state, and receipt correlations;
it does not expose request bodies or control JSON. A user who is not a member
of the binding's entity execution role sees no rows if they have schema access;
other roles cannot select the view.

Install `integrations/pg-mdm/sql/operational-activity.sql` after
`intent-worker.sql` as a database administrator with access to the adapter's
intent tables and `pgreact.work`. Queries over `pgreact.operational_status` or
`pgreact.attempts` use private core relations; run those queries as the pg-react
object owner or a superuser. The overdue-case query uses the row-scoped work
state from `operational_activity_v1` and can run as the entity role. The
reporting interval, retention horizon, binding ID, and rule names below come
from the approved qualification manifest; do not substitute example values
for approved limits.

In psql, set `report_interval`, `retention_horizon`, `binding_id`, and
`adapter_rule_names` from that manifest before running the matching query.
The current [v0.50 qualification manifest](../tests/integrations/pg-mdm/evidence/v0.50.0/manifest.json)
is blocked. Derive its release decision with
`python3 tests/integrations/pg-mdm/derive_v050_qualification.py`; local fixture
checks do not qualify the joint release. A passed gate must retain evidence
files beside the manifest with relative paths and verified SHA-256 digests.
The structured release record also requires the workload owner, frozen
membership and policy revisions, complete shadow counts, approved numeric
limits and observation interval, threshold approvals, support documents, and
three distinct final sign-offs. Missing or inconsistent values block derivation.
The accepted-publication classification below requires the exact MDM public
projection and outcome mapping to be frozen in that manifest; until then show
`UNAVAILABLE_PUBLICLY` rather than zero.

## Stale-intent rate

Pass `report_interval` as a psql variable. The denominator counts classified
attempt rows, not distinct cases or requests. A zero denominator returns
`NO_SAMPLES` and a null rate.

```sql
WITH sample AS (
    SELECT clock_timestamp() - :'report_interval'::interval AS since
), counts AS (
    SELECT count(*) FILTER (
               WHERE activity.attempted_at IS NOT NULL
           ) AS classified_attempts,
           count(*) FILTER (
               WHERE activity.attempted_at IS NOT NULL
                 AND (activity.delivery_outcome IN (
                          'STALE_CASE', 'CASE_CLOSED', 'BINDING_REPLACED',
                          'POLICY_MISMATCH', 'SUPERSEDED')
                      OR activity.delivery_reason_code LIKE 'STALE_%'
                      OR activity.delivery_reason_code LIKE 'SUPERSEDED_%'
                      OR activity.mdm_reason_code LIKE 'STALE_%'
                      OR activity.mdm_reason_code LIKE 'SUPERSEDED_%')
           ) AS stale_or_superseded_attempts
    FROM pgreact_mdm.operational_activity_v1 AS activity
    CROSS JOIN sample
    WHERE activity.binding_id = :'binding_id'::uuid
      AND activity.attempted_at >= sample.since
)
SELECT stale_or_superseded_attempts,
       classified_attempts,
       stale_or_superseded_attempts::numeric
           / NULLIF(classified_attempts, 0) AS stale_intent_rate,
       CASE WHEN classified_attempts = 0 THEN 'NO_SAMPLES' ELSE 'SAMPLED' END AS sample_state
FROM counts;
```

Review stale and superseded reasons with the workload owner. Correct policy or
binding drift, then create new work through the authorized reevaluation path;
never edit or resend an attempted request.

## Denied, invalid, conflict, and worker failures

This result preserves each observed outcome and reason. Known terminal MDM
policy outcomes are separated from conflicts; unrecognized outcomes remain
visible as `UNCLASSIFIED` and block automated retry decisions.

```sql
WITH observed AS (
    SELECT delivery_outcome, delivery_reason_code, mdm_outcome,
           mdm_reason_code, mdm_receipt_id
    FROM pgreact_mdm.operational_activity_v1
    WHERE binding_id = :'binding_id'::uuid
      AND attempted_at >= clock_timestamp() - :'report_interval'::interval
), classified AS (
    SELECT CASE
               WHEN delivery_outcome = 'IDEMPOTENCY_CONFLICT' THEN 'CONFLICT'
               WHEN delivery_outcome = 'INVALID' THEN 'INVALID'
               WHEN delivery_outcome = 'RECOVERY_BLOCKED' THEN 'RECOVERY_BLOCKED'
               WHEN delivery_outcome IN (
                   'ACTION_DENIED', 'MANUAL_PROTECTION', 'OPENED_AT_UNKNOWN',
                   'LIMIT_EXCEEDED', 'BINDING_PAUSED', 'BINDING_REPLACED',
                   'POLICY_MISMATCH', 'PENDING_STEWARDSHIP', 'STALE_CASE',
                   'CASE_CLOSED', 'SUPERSEDED')
                   THEN 'POLICY_OR_CONFIGURATION'
               WHEN mdm_receipt_id IS NOT NULL
                    AND mdm_outcome = 'APPLIED_CONTROL'
                   THEN 'ACCEPTED_CONTROL_PUBLICATION_UNKNOWN'
               WHEN delivery_outcome IN ('APPLIED_CONTROL', 'NO_CHANGE', 'APPLIED_PUBLICATION')
                   THEN 'SUCCESS'
               ELSE 'UNCLASSIFIED'
           END AS failure_class,
           delivery_outcome, delivery_reason_code, mdm_outcome, mdm_reason_code
    FROM observed
), counts AS (
    SELECT count(*) AS sample_count FROM classified
), outcome_counts AS (
    SELECT failure_class, delivery_outcome, delivery_reason_code, mdm_outcome,
           mdm_reason_code,
           count(*) AS attempt_count
    FROM classified
    GROUP BY failure_class, delivery_outcome, delivery_reason_code,
             mdm_outcome, mdm_reason_code
)
SELECT counts.sample_count,
       CASE WHEN counts.sample_count = 0 THEN 'NO_SAMPLES' ELSE 'SAMPLED' END AS sample_state,
       outcome_counts.failure_class,
       outcome_counts.delivery_outcome,
       outcome_counts.delivery_reason_code,
       outcome_counts.mdm_outcome,
       outcome_counts.mdm_reason_code,
       coalesce(outcome_counts.attempt_count, 0) AS attempt_count
FROM counts
LEFT JOIN outcome_counts ON true
ORDER BY outcome_counts.failure_class, outcome_counts.delivery_outcome,
         outcome_counts.delivery_reason_code, outcome_counts.mdm_outcome;
```

Use `pgreact.attempts` for worker execution failures that rolled back before an
MDM receipt was recorded. Treat an unknown MDM outcome or error code as a
pause-and-investigate condition. Retry only outcomes classified as transient
by the pinned MDM contract. `pgreact.attempts` and
`pgreact.operational_status` require the existing advanced operator privileges;
the row-scoped activity projection can run as the entity execution role.

```sql
WITH classified AS (
    SELECT CASE
               WHEN attempt.status = 'FAILED' AND work.state = 'RETRY_WAIT'
                   THEN 'RETRYING_FAILURE'
               WHEN attempt.status = 'FAILED' AND work.state = 'FAILED'
                   THEN 'TERMINAL_FAILURE'
               ELSE attempt.status
           END AS execution_class,
           attempt.status, work.state AS current_work_state,
           attempt.error_code, count(*) AS execution_count
    FROM pgreact.attempts AS attempt
    JOIN pgreact.work AS work
      ON work.kind = 'rule'
     AND work.work_id = attempt.episode_id::text
    WHERE work.name = ANY (:'adapter_rule_names'::text[])
      AND attempt.started_at >= clock_timestamp() - :'report_interval'::interval
    GROUP BY attempt.status, work.state, attempt.error_code
), totals AS (
    SELECT coalesce(sum(execution_count), 0) AS sample_count
    FROM classified
)
SELECT totals.sample_count,
       CASE WHEN totals.sample_count = 0 THEN 'NO_SAMPLES' ELSE 'SAMPLED' END AS sample_state,
       classified.execution_class, classified.status,
       classified.current_work_state, classified.error_code,
       coalesce(classified.execution_count, 0) AS execution_count
FROM totals
LEFT JOIN classified ON true
ORDER BY classified.execution_class, classified.current_work_state,
         classified.error_code;
```

## Overdue open cases

The query evaluates the pinned deadline policy at one database-time sample.
The scoped activity projection carries current React work state, so this query
can run as the entity execution role.
Its eligible denominator includes open, non-pending cases with no current due
date and cases where the pinned preview returns a proposed, preserved, or
replacement due date. Overdue counts and age use the current stored due date
returned as `existing_due_at`; a preview proposal alone does not change the
deadline or make a case overdue. The query reports missing work separately and
does not propose a replacement due date.

```sql
WITH sample AS (
    SELECT clock_timestamp() AS captured_at
), eligible AS (
    SELECT binding.binding_id,
           policy_case.case_key,
           preview.existing_due_at,
           preview.decision,
           sample.captured_at,
           EXISTS (
               SELECT 1
               FROM pgreact_mdm.operational_activity_v1 AS activity
               WHERE activity.binding_id = binding.binding_id
                 AND activity.case_key = policy_case.case_key
                 AND activity.action = 'SET_DUE_AT'
                 AND activity.react_work_state IN ('PENDING', 'LEASED', 'RETRY_WAIT')
           ) AS has_pending_work
    FROM pgreact_mdm.policy_intent_bindings AS binding
    JOIN mdm_steward.policy_cases_v1 AS policy_case
      ON policy_case.entity_name = binding.entity_name
    CROSS JOIN sample
    CROSS JOIN LATERAL pgreact_mdm.deadline_preview(
        'mdm_steward.policy_cases_v1'::regclass,
        binding.policy_revision,
        sample.captured_at,
        binding.entity_name::text
    ) AS preview
    WHERE binding.binding_id = :'binding_id'::uuid
      AND 'SET_DUE_AT' = ANY(binding.allowed_actions)
      AND policy_case.status = 'open'
      AND NOT policy_case.pending_stewardship
      AND preview.decision IN ('PROPOSED', 'PRESERVED', 'REPLACEMENT')
      AND preview.case_key = policy_case.case_key
)
SELECT count(*) AS eligible_open_cases,
       count(*) FILTER (WHERE existing_due_at <= captured_at) AS overdue_case_count,
       count(*) FILTER (
           WHERE existing_due_at <= captured_at AND NOT has_pending_work
       ) AS overdue_without_pending_work,
       max(captured_at - existing_due_at)
           FILTER (WHERE existing_due_at <= captured_at) AS oldest_overdue_age,
       max(captured_at) AS captured_at,
       CASE WHEN count(*) = 0 THEN 'NO_ELIGIBLE_CASES'
            WHEN count(*) FILTER (WHERE existing_due_at <= captured_at) = 0
                THEN 'NO_OVERDUE_CASES'
            ELSE 'SAMPLED' END AS sample_state
FROM eligible;
```

Have the workload owner investigate overdue cases without pending work through
the approved MDM workflow. Preserve existing due dates unless an authorized
policy replacement explicitly changes them.

## Work backlog and drain

Use the existing per-rule operational view, restricted to the exact adapter
rule names recorded in the manifest. Capture `outstanding_episodes`,
`oldest_eligible_at`, failed episodes, and blocked claims before a declared
burst and after each declared drain interval. Keep each timestamped sample;
do not infer a drain rate from one snapshot. Count adapter-held requests from
`operational_activity_v1` where `remediation_state = 'HELD'`.

```sql
WITH sample AS (
    SELECT clock_timestamp() AS captured_at
), selected_rules AS (
    SELECT rule_name::text AS rule_name, state, outstanding_episodes,
           oldest_eligible_at, failed_episodes, claims_blocked,
           sample.captured_at
    FROM pgreact.operational_status
    CROSS JOIN sample
    WHERE rule_name::text = ANY (:'adapter_rule_names'::text[])
)
SELECT rule_name, state, outstanding_episodes, oldest_eligible_at,
       failed_episodes, claims_blocked, 'SAMPLED' AS sample_state, captured_at
FROM selected_rules
UNION ALL
SELECT NULL::text, NULL::text, NULL::bigint, NULL::timestamptz,
       NULL::bigint, NULL::boolean, 'NO_RULE_SAMPLES', sample.captured_at
FROM sample
WHERE NOT EXISTS (SELECT 1 FROM selected_rules)
ORDER BY rule_name;
```

Count the active states at the same snapshot. This query returns zero for a
state with no work and `NO_RULE_SAMPLES` when none of the named rules appears
in the operational view.

```sql
WITH selected_rules AS (
    SELECT count(*) AS rule_count
    FROM pgreact.operational_status
    WHERE rule_name = ANY (:'adapter_rule_names'::text[])
), states(state) AS (
    VALUES ('PENDING'::text), ('LEASED'), ('RETRY_WAIT')
), counts AS (
    SELECT work.state, count(*) AS episode_count
    FROM pgreact.work AS work
    WHERE work.kind = 'rule'
      AND work.name = ANY (:'adapter_rule_names'::text[])
      AND work.state IN ('PENDING', 'LEASED', 'RETRY_WAIT')
    GROUP BY work.state
)
SELECT states.state,
       coalesce(counts.episode_count, 0) AS episode_count,
       CASE WHEN selected_rules.rule_count = 0 THEN 'NO_RULE_SAMPLES'
            ELSE 'SAMPLED' END AS sample_state
FROM states
CROSS JOIN selected_rules
LEFT JOIN counts USING (state)
ORDER BY states.state;
```

```sql
SELECT count(DISTINCT (binding_id, work_ref)) FILTER (
           WHERE remediation_state = 'HELD'
       ) AS held_requests,
       coalesce(array_agg(DISTINCT remediation_reason_code) FILTER (
           WHERE remediation_state = 'HELD'
       ), ARRAY[]::text[]) AS held_reasons,
       CASE WHEN count(*) = 0 THEN 'NO_REQUEST_SAMPLES'
            WHEN count(*) FILTER (WHERE remediation_state = 'HELD') = 0
                THEN 'ZERO_HELD'
            ELSE 'HELD' END AS sample_state
FROM pgreact_mdm.operational_activity_v1
WHERE binding_id = :'binding_id'::uuid;
```

If backlog, age, or failures exceed the approved limits, stop cohort expansion,
apply the declared backpressure or pause procedure, and retain the samples.

## Repeated escalation attempts

Retries of the same `work_ref` within a binding are one immutable request.
Distinct work refs for one case and level are distinct requests. More than one
applied control for a case-level pair is a correctness failure.

```sql
WITH requests AS (
    SELECT binding_id, work_ref, case_key, escalation_level,
           count(*) FILTER (WHERE attempted_at IS NOT NULL) AS attempt_count,
           bool_or(mdm_outcome = 'APPLIED_CONTROL') AS applied
    FROM pgreact_mdm.operational_activity_v1
    WHERE binding_id = :'binding_id'::uuid
      AND action = 'ESCALATE'
    GROUP BY binding_id, work_ref, case_key, escalation_level
), levels AS (
    SELECT case_key, escalation_level,
           count(*) AS distinct_requests,
           sum(greatest(attempt_count - 1, 0)) AS retries_of_same_request,
           count(*) FILTER (WHERE applied) AS applied_requests
    FROM requests
    GROUP BY case_key, escalation_level
), totals AS (
    SELECT count(*) AS sampled_case_levels,
           coalesce(sum(distinct_requests), 0) AS distinct_requests,
           coalesce(sum(retries_of_same_request), 0) AS same_request_retries,
           coalesce(count(*) FILTER (WHERE applied_requests > 1), 0) AS duplicate_applied_levels
    FROM levels
)
SELECT *,
       CASE WHEN sampled_case_levels = 0 THEN 'NO_SAMPLES' ELSE 'SAMPLED' END AS sample_state
FROM totals;
```

Any `duplicate_applied_levels > 0` triggers immediate pause and investigation.
Do not resend an accepted request to force publication.

## Accepted controls and publication visibility

The selected MDM-STEWARDSHIP/1 receipt contract sets
`resulting_publication_revision` to null for every intent and exposes no
receipt-to-later-publication correlation.
`pending_stewardship` tracks decision-epoch freshness and blocks controls; it
does not report output publication. Count accepted controls, but report their
publication state and age as `UNAVAILABLE_PUBLICLY` until MDM exposes that
correlation. Do not infer publication from React work completion, request time,
the case's basis revision, or `last_observed_at`.

```sql
SELECT count(DISTINCT (binding_id, work_ref)) FILTER (
           WHERE mdm_receipt_id IS NOT NULL
             AND mdm_outcome = 'APPLIED_CONTROL'
       ) AS accepted_control_requests,
       NULL::interval AS oldest_publication_age,
       CASE WHEN count(DISTINCT (binding_id, work_ref)) = 0 THEN 'NO_REQUEST_SAMPLES'
            WHEN count(DISTINCT (binding_id, work_ref)) FILTER (
                    WHERE mdm_receipt_id IS NOT NULL
                      AND mdm_outcome = 'APPLIED_CONTROL'
                ) = 0 THEN 'NO_ACCEPTED_CONTROL_SAMPLES'
            ELSE 'UNAVAILABLE_PUBLICLY' END AS publication_state
FROM pgreact_mdm.operational_activity_v1
WHERE binding_id = :'binding_id'::uuid;
```

Keep receipt-backed accepted controls visible while MDM publication recovery
proceeds. Do not create replacement work or resend the accepted control.

## Retention coverage

Pass the approved `retention_horizon`. The query checks request and receipt
correlation within that horizon. Historical evidence-version retention is not
exposed by the approved public projection and must be reported as unavailable
until MDM provides a public check for it.

```sql
WITH in_horizon AS (
    SELECT binding_id, work_ref,
           bool_or(mdm_receipt_id IS NOT NULL) AS has_receipt_id,
           bool_and(mdm_receipt_retained) FILTER (WHERE mdm_receipt_id IS NOT NULL)
               AS receipts_retained
    FROM pgreact_mdm.operational_activity_v1
    WHERE binding_id = :'binding_id'::uuid
      AND requested_at >= clock_timestamp() - :'retention_horizon'::interval
    GROUP BY binding_id, work_ref
), coverage AS (
    SELECT count(*) AS retained_requests,
           count(*) FILTER (WHERE has_receipt_id) AS requests_with_receipt_id,
           count(*) FILTER (WHERE has_receipt_id AND receipts_retained) AS retained_receipts,
           count(*) FILTER (WHERE has_receipt_id AND NOT receipts_retained) AS missing_receipts
    FROM in_horizon
)
SELECT *,
       CASE WHEN missing_receipts > 0 THEN 'GAP'
            WHEN retained_requests = 0 THEN 'NO_SAMPLES'
            WHEN requests_with_receipt_id = 0 THEN 'NO_RECEIPT_SAMPLES'
            ELSE 'REQUEST_RECEIPT_COVERED' END AS coverage_state,
       'UNAVAILABLE_PUBLICLY' AS evidence_version_coverage
FROM coverage;
```

Any missing receipt blocks recovery and admission. Missing observations are not
zero coverage, and this query does not establish an agreed horizon by itself.

## Dashboard specification

Group panels into three operator questions: **Is policy behavior safe?** shows
stale rate and denied/invalid/conflict reasons; **Is work inside its budget?**
shows overdue age, backlog/drain, held requests, and escalation retries; **Can
we still recover and reconcile?** shows accepted controls with publication
visibility, publication-age state, and retention coverage. Include the report
interval, sample state, approved limit, current value, and remediation state on
each panel. Display `NO_SAMPLES`,
`NO_OVERDUE_CASES`, and `UNAVAILABLE_PUBLICLY` distinctly from numeric zero.
Restrict case-level drill downs to the entity execution role; otherwise show
only counts, ages, outcome codes, and public work references. The dashboard is
a specification only; no new UI or monitoring backend is required.

## Cohort admission and recovery gates

The release manifest must name the workload owner, stable cohort predicate or
membership set, policy revisions, expected exceptions, observation period,
and exact artifact tuple before the first comparison. Record measured numeric
limits after baseline collection and obtain operator and release-owner approval
before the final qualifying run. Missing values keep the corresponding gate
blocked.

For a fixed set, retain a membership JSON object with exactly `schema_version`
(`1`), `population_id`, and sorted, unique positive PostgreSQL `bigint`
`case_keys`. `cohort.membership_sha256` is the file digest, and
`shadow.reference_population_sha256` must match it. Retain the frozen package
artifact at `cohort.package_manifest`; its file digest must equal
`cohort.package_digest`.

### Shadow approval

Capture one reference population and policy version pair. Run
`pgreact_mdm.compare_population()` against the fixed set or its disjoint
partitions and retain each complete JSON result. Admission requires
`state = 'complete'`, `coverage.partial = false`, matching expected and observed
counts, and exact once-only coverage of every frozen case key. A partial result,
missing partition, duplicate key, or changed membership invalidates approval.
Store `shadow.coverage_manifest` as a JSON array of those results. Use the
frozen `population_id`, the explicit `coverage.membership` list, a common
`captured_at`, and declared `current` and `proposed` policy revisions in every
partition. The release derivation checks partition membership against each
result's rows and checks the union against the frozen membership file.
Each row retains current and proposed queues, assignment decisions and reasons,
manual protections, stored and proposed due dates, and escalation levels so the
owner can review no-ops and protected cases as well as changed actions.

The workload owner reviews the full current and proposed assignment, due date,
no-op, protected-case, and escalation output. Record manual exceptions and
freeze the reviewed package digest. Keep the result read-only; comparison does
not authorize an MDM control.

### Staged enablement

Advance in order, retaining the gate result at each stage:

1. **Installed, effects disabled:** verify the exact artifact tuple, admission,
   grants, MDM contract, and core-only no-effect behavior.
2. **Shadow:** complete population coverage, workload-owner review, and package
   digest freeze.
3. **Cohort routing and deadlines:** enable only the approved actions and fixed
   cohort; compare complete MDM controls and receipts and confirm human
   protections.
4. **Cohort escalation:** proceed only after routing/deadline behavior and
   real-time tests remain healthy; verify the configured maximum and one-level
   progression.
5. **Supported profile:** finish the declared observation period, meet approved
   operating limits, and obtain operator and independent release sign-off.

Approval support stays disabled. Expanding membership or actions requires a
reviewed binding or policy change. Do not use a successful fixture or earlier
stage as evidence for a later stage.

### Pause, upgrade, and restore

Pause immediately on an unauthorized control, duplicate applied escalation,
stale-binding acceptance, unexplained population omission, lost recovery
coherence, or unexplained capability change. Stop expansion and apply the
declared backpressure or pause on an operating-limit overrun. As the
entity execution role, call
`pgreact_mdm.pause_intent_binding(binding_id, expected_runtime_version)` and
wait for the acknowledged barrier. No new intent is accepted after that
barrier; controls accepted before it remain visible and are not reversed.

Before upgrade, inventory pending work and preserve one coherent database
backup with its matching binaries, requests, attempts, bindings, receipts, and
publication state. Upgrade with effects disabled, verify the exact artifacts
and capability response, then explicitly reconcile and resume. On restore,
start with managed effects disabled and keep copied clone state inert until an
independent activation check succeeds. Restore the complete coherent pair;
never restore React request state separately from MDM receipts. Follow the
[v0.49 recovery procedure](v0.49-qualification.md#operator-procedure) until
the v0.50 joint run records an exact replacement procedure.

The Oct 27 baseline regression recorded logical restore data loss. The selected
v0.49 profile later passed its repeated 48-check logical-restore audit, and the
current assembled SQL registers managed tables with `pg_extension_config_dump`.
That evidence does not qualify logical or physical restore on the final v0.50
tuple. Keep recovery admission blocked until the complete v0.50 restore drill
passes. See the [v0.49 disposition](v0.49-qualification.md) and
[support matrix](v0.50.0-support-matrix.md).

The shared MDM and React qualification is still required for each stage. This
runbook does not name a workload, claim measured capacity, or authorize cohort
admission on its own.
