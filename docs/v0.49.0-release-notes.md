# pg-react MDM adapter 0.49.0

This limited release adds time-driven managed escalation and recovery support
to the optional pg-react MDM adapter. The pg-react extension version remains
separate from the adapter version. The supported profile below describes the
tested operating envelope; it is not a guarantee outside that profile.

## Included

- Managed cases can become due through database time alone. Each evaluation
  advances at most one permitted level, through level 2.
- The reference producer accepts at most 300 admissions per invocation,
  groups up to five admissions per refresh, and commits source changes before
  each separate MDM refresh call. Exact request replay preserves the original
  row; a conflicting body on the same key is rejected.
- Retention guards, a daily health monitor, and recovery guidance cover
  coherent restore, identity rebinding, explicit activation, and retained
  receipts.
- Optional systemd service and timer files show one deployment pattern. They
  have not been host-tested or deployed.

## Supported initial operating profile

| Setting | Supported limit |
| --- | --- |
| Tested stack | PostgreSQL 18.4, pg-react 0.46.1, pg-mdm 0.14.2, pg-trickle 0.108.4 |
| Managed poll / claims | 1 second / at most 32 claims per cycle |
| Escalation | One next level per evaluation; maximum level 2 |
| Offered load | 300 admissions at 60 per minute over five minutes |
| Minimum accepted throughput | 40 admissions per minute |
| Simultaneously due cases | 1,000 |
| Due delivery latency | p95 at most 150 seconds; maximum 180 seconds |
| Detection, dispatch, and backlog drain | At most 180 seconds each |
| Supported PostgreSQL outage / recovery | At most 120 / 180 seconds |
| Peak sampled memory | Below 4 GiB |
| WAL / row writes / supervised storage | At most 4 GiB / 10,000,000 / below 10 GiB |
| Duplicate, unauthorized, stale-binding, or pre-activation actions | Zero |
| Request, key, and receipt retention | Entire occurrence lifetime, then at least 90 days |

The paired candidate/control workload passed on the selected profile and
exceeded the 40-per-minute floor. Measurements used Linux/AMD64 images on the
controlled ARM64 host under emulation; they do not establish native ARM64
performance or capacity on other hardware.

## Accepted limits and follow-up

- The sole maintainer accepted a limited release after focused internal review
  and green candidate checks. A separate external independent review was
  waived; none is claimed.
- The exact-wheel physical-clone candidate passed, while its matched control
  stopped at the host free-space guard. The separate paired candidate/control
  workload and outage run passed, and the candidate clone and logical restore
  checks passed. The release manifest records this tradeoff.
- Coherent backups and matching binaries must be retained for at least 90 days.
  Automatic and React M21 pruning remain disabled. After the first 90-day
  archive has actually been retained, verify a restore from it before enabling
  any pruning. Backdated boundary tests do not substitute for that restore.
- No customer application adoption or production deployment is included.
  Application rollout follows publication and must stay within the profile.
