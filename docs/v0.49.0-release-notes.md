# pg-react MDM adapter 0.49.0 — draft release notes

> Draft only. Version 0.49.0 has not been released or qualified. Do not publish
> these notes or treat the selected qualification profile as a production
> service guarantee.

This candidate adds time-driven managed escalation and recovery support to the
optional pg-react MDM adapter. The core pg-react extension version remains
separate from the adapter version.

## Candidate changes

- Managed cases can become due through database time alone. Each evaluation
  advances by at most one escalation level, through level 2; delayed polling
  does not cause skipped-level or catch-up bursts.
- A bounded reference producer accepts at most 300 admissions per invocation,
  groups up to five admissions per refresh, and commits source changes before
  each separate `mdm.refresh()` call. Identical request replay preserves the
  original row; a conflicting body on the same request key is rejected.
- Managed case and receipt history has explicit retention guards and a health
  monitor. Optional systemd service and timer files show one deployment pattern;
  they have not been host-tested or deployed.
- Recovery guidance covers logical restore, binding and relation identity
  rebinding, explicit activation, and post-restore retention-health checks.

## Candidate evidence

The installed reference-producer wheel passed 18 focused checks and completed
300 admissions at 59.851792 admissions per minute under a 60-per-minute offered
load. A current-source candidate/control outage pair passed 34 checks per arm,
completed all 300 admissions and 1,000 due cases, and remained within the
measured outage, recovery, latency, WAL, row-write, memory, and storage limits.
These are local harness measurements, not production guarantees. The raw
qualification decisions remain `INPUT_BLOCKED` and `release_qualified=false`.
