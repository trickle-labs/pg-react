## Independent work in this change

The routing evaluator accepts an explicit finite `captured_at`, preserving the
two existing signatures and their result shapes. Population comparison now uses
its supplied sample for escalation routing as well as deadline proposals.
Complete result vectors cover before/equal/after due time, equivalent timezone
instants, repeated and backward samples, unchanged source rows, entity filtering,
invalid samples, legacy calls, and a maximum integer current level.

The existing temporal entry points are
`pgreact_api.author_deadline_rule(..., deadline_column, ...)` and the ordinary
managed worker's `pgreact_api.run()` path. The stored deadline is compared with
the sampled clock frontier; public `pgreact_api.deadline_history(name)` exposes
the declared deadline and frontier. The existing
[`time/boundaries.sql`](../tests/integrations/pg-mdm/time/boundaries.sql),
[`time/idle.sql`](../tests/integrations/pg-mdm/time/idle.sql), and
[`time/audit.py`](../tests/integrations/pg-mdm/time/audit.py) are audit inputs,
not fresh qualification evidence for this change.

This patch creates no temporal registration or action bookkeeping and enables
no new automation on installation. Reinstall `routing.sql` before
`comparison.sql` to update an existing optional adapter. Request codecs,
attempted requests and explicit binding activation are unchanged.
