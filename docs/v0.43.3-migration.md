# pg-react 0.43.3 migration

The adjacent upgrade is from pg-react 0.43.2:

```sql
ALTER EXTENSION pg_react UPDATE TO '0.43.3';
SELECT extname, extversion FROM pg_extension
WHERE extname IN ('pg_react', 'pg_trickle') ORDER BY extname;
SELECT pgreact.doctor();
```

Before the update, stop managed workers and application writes, take a
consistent stopped-cluster physical backup, and record the full declarations,
owners, versions, queue, attempts, leases, frontiers, and application effects.
Keep the old 0.43.2 image digest with that backup.

The migration adds agenda activity timestamps. Existing rows retain a
provable timestamp only when one already exists; otherwise `updated_at` is
NULL. New inserts, claims, retries, sweeps, cancellations, and completions
receive accurate timestamps. Resume workers only after comparing the complete
post-update state with the snapshot.

If rollback is required, stop the candidate cluster and restore the stopped
backup with the matching 0.43.2 image and pg_trickle dependency. Do not mix
extension SQL, container versions, or physical data directories.
