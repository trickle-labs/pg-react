# v0.50.0 candidate support matrix

**Status: not qualified; no v0.50.0 configuration is supported yet.** This
matrix records the intended narrow scope and the evidence still required. It
does not authorize deployment.

| Area | Intended boundary | Current status |
|---|---|---|
| Runtime artifacts | Exact PostgreSQL, pg-react, pg-trickle, pg-mdm, image, shared-library, contract, and adapter digests in the final manifest | Not pinned or jointly qualified |
| Workload | One named administrative domain and a frozen, workload-owner-reviewed cohort using the approved non-RLS projection | No owner or cohort recorded |
| Controls | Queue assignment, due-date control, and configured bounded escalation; MDM remains authoritative | Real-stack failure suite and staged cohort run not complete |
| Approval | Approval policy/write support remains disabled | Not supported in this profile |
| Publication | Distinguish accepted controls from later MDM publication and report pending age and stewardship age | Fixture queries target merged MDM 0.15.0 candidate contract v4; no package release or real-cohort result is qualified |
| Recovery | Coherent whole-database backup with matching artifacts, effects disabled on restore/clone, then explicit reconciliation | Prior v0.49 selected profile passed a repeated 48-check logical-restore audit; v0.50 final-tuple recovery and clone activation remain unqualified |
| Performance | Case, churn, backlog, latency, retention, and recovery thresholds measured on the named workload | No baseline or approved numeric limits |
| Other platforms and scopes | No broader tenant/RLS, transport, approval, or unattended mass-rollout claim | Out of scope |

See the [draft release notes](v0.50.0-release-notes.md), [operator guide](v0.50.0-operations.md),
and [qualification manifest](../tests/integrations/pg-mdm/evidence/v0.50.0/manifest.json).
